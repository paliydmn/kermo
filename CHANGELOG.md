## [Unreleased]

### Security

- A locked server reached by an `~/.ssh/config` alias or another spelling now gets a locked server's 60-second connection linger, not 10 minutes, and isn't added to the recents. A tunnel edited to a new address while a locked server is saved stays off until **Turn On** asks.
- A root panel no longer goes into a folder that someone else on the server can change (not root's, or writable by its group or others without the sticky bit) when it deletes, copies or moves a tree. Such a folder's owner could swap what's in it for a link to `/` between two steps, and root would delete or write there. Such folders are left as they are and named in the summary.
- A locked server's Touch ID and a production server's purple mark, questions and log now go with the server, not with how its address is written: an `~/.ssh/config` alias of it, `ROOT@host`, a trailing dot or a left-out user no longer get past them.
- A file from a server or from inside an archive that ↩ (or Quick Look's **Open with**) opens in another app is now quarantined first, so Gatekeeper checks it: a `.command` script from a server no longer runs in Terminal at once. A file from a quarantined archive keeps the archive's own quarantine.
- **Save as Administrator** no longer writes from a file that something else running as you could change while macOS asks for the password: the text goes to root in the command itself (a text over about 500 KB goes through a file root checks against your text). It never leaves the file empty when the disk is full, and a change made to the file while the password dialog was up now asks "changed on disk" instead of being overwritten.
- **Copy as Administrator** and **Move as Administrator** now check what F5 and F6 check, before the password is asked. They refuse to copy a folder into itself (`ditto` as root filled the disk with copies of it) and to go through a link that has the item's name in the destination folder (root wrote where it pointed). Copy also asks before it replaces what's there.
- **Save as Administrator** can no longer be made to write through a link that something running as you swaps in at the last moment: root opens the file without following links and checks it's still the file you edited before it writes.
- On a production server the question before a command now looks at every command in the line, not only the first word: `cd /srv && rm -rf releases/*`, `ls; rm x`, `… | xargs rm` and `$(…)` ask too. So do `find -delete`, `truncate`, `rsync --delete`, `git clean`, `git reset --hard`, `systemctl disable` and writing over a file with `>`.

### Changed

- ↩ on a file inside an archive opens a read-only copy, and the status line says so: the copy lives in a temporary folder that goes a day later, so edits made to it in another app were lost. The app now says it's locked and offers to duplicate it; Extract (⌥F9) keeps a copy of your own.

### Fixed

- Opening an archive with a very deeply nested path (a tiny zip with one file 2000 folders down) no longer crashes Kermo.
- Copying a file locked in Finder works: the copy is locked too, as Finder's is. Before, it failed with "Operation not permitted" and left a hidden, locked partial file in the destination; such leftovers are now cleared after a day like the others.
- **Save As…** of a server file's editor makes it an ordinary local file: a later revert from that server file's history no longer writes the old version into the file you saved.
- Saving a server file through a symlink (nginx's `sites-enabled`), someone else's file, or from a root panel under SELinux can no longer leave the file empty when the connection drops. A symlink's target is now replaced whole and the link stays a link. A root panel keeps the owner of someone else's file and still replaces it whole. What's still written into the file is written over the old text and cut to length only at the end.
- If a save that writes into the server's file fails on the way, the old text is put back when the connection still works. The message says whether the file on the server was put back or may be cut short, and names the partial file there that has your full text. Before, it said only that the upload failed.
- Temporary files a crash left behind are cleared: partial files of server saves (at a later save in that folder, once a day old), the local editor's save files, and those of **Save as Administrator** and a config check's put-back. **Save as Administrator**'s temporary copy of the text is now readable only by you.
- On a server with SELinux, saving a file from any panel keeps its SELinux label. Before, only a root panel did; a login as root or as yourself gave the saved file its folder's label (`/etc/shadow` losing `shadow_t`, a page in `~/public_html` answering 403).
- Extracting a zip, 7z or other archive, or entries from inside any archive, over files that are already there can no longer leave one of them gone and the new one cut short when you stop it, the disk fills up or the archive is broken midway: it unpacks into a hidden folder first, as all of a tar already did, and nothing lands unless it all worked; the output window then says the files are as they were.
- Saving a hard-linked file, or someone else's file in a folder you can write, in the editor can no longer leave it empty when the disk fills up or the write fails midway: the text is written over the old one and the file is cut to length only at the end.
- **Split File…** no longer writes over parts of an earlier split when `.000` is gone but later parts are there, and **Combine Parts…** refuses parts of different sizes (two splits mixed) instead of joining them into garbage. Both now read the folder off the main thread.
- **Move To…** (F6) to the same name in another case (`Foo` → `foo`) renames the item. Before, it asked whether to merge it with itself and then left the name as it was.
- Overwriting a folder on a server with a file (or a file with a folder) no longer deletes the old one before the new one is there: a copy that failed midway left neither. The new one is copied under a temporary name first and replaces the old one only once it's whole.
- **Delete Permanently…** (⇧F8) and **Move To…** (F6) to another volume no longer go into a volume mounted inside the folder: ⇧F8 on a folder holding a mounted share used to empty the share. They stop there, as `rm -r --one-file-system` does, and the summary names it.
- **Synchronize Folders** deleting a folder on a server no longer takes along what was put in it after the comparison (a file written there, a folder moved in): that stays, with the folders above it, and the summary names it.
- Undo of a copy or a new file, and **Put Back**, act only on the item they recorded. If you renamed it in Finder and something else took its name, that other item no longer goes to the Trash or back to the old place; Kermo names it instead. `trash.json` now records each item's inode; an older Kermo can't read the new form.
- One entry in `servers.json` that can't be read (a hand edit such as `"port": "22"`) no longer empties the list of saved servers: only that entry is left out. Kermo says at launch what it left out and where the file as it was is kept (`servers.json.broken`, copied, not moved).
- A broken `bookmarks.json`, `server-pins.json`, `frecency.json` or `trash.json` is no longer quietly replaced with an empty one at the next save: it's copied to `name.broken` first and Kermo says so. In bookmarks and pins only the entries that can't be read are left out.
- Logged in to a server as `root` (not through a root panel), saving someone else's file now replaces it whole and gives it back its owner, as a root panel does. Before, it was written into in place.
- The history of saved server files always stays out of Time Machine. Before, only a history folder this version created was left out; one from an older version was backed up, server secrets included.
- A damaged folder sort setting (`defaults write … folderSort` with an empty value) no longer crashes Kermo every time that folder opens: it sorts by name.
- A hostile or broken SFTP server can no longer crash Kermo by reporting huge file sizes: the size of a folder (⌥Space), the scan before a copy and the status line's total stop at the largest size instead of overflowing. Nor can it fill memory with answers to requests Kermo never made (or answers sent twice): they're dropped, and a server holding back more than 64 MB of answers ends the connection with a protocol error.
- ⌘L ⇥ on a server that took the connection and stopped answering no longer holds a connection and a thread for every ⇥: the next ⇥, leaving the path field or five seconds end it, quietly.
- The output window (⌘E, F2) no longer grows without end in memory when a command prints a flood (`cat /dev/urandom | base64`) while Kermo is busy with a sheet: past 8 MB the oldest output not shown yet goes, as the window keeps only the last 4 MB anyway. A read error on the command's output ends it instead of crashing Kermo.
- When `/tmp/dfm-ssh-<uid>` belongs to someone else, the random folder Kermo uses for its ssh connections instead is removed at quit; one was left in `/tmp` after every run.
- Quitting Kermo no longer hangs on a server connection that stopped answering: closing each takes at most 2.5 seconds, and all of them close at once.
- Opening an archive with a path tens of thousands of folders deep no longer takes a gigabyte of memory: the list of what's inside is kept folder by folder. And quitting Kermo during an extract removes the hidden folder it was unpacking into instead of leaving a copy of the archive's contents for a day.
- **Delete Permanently…** (⇧F8) on a server, and **Move To…** (F6) off a server, no longer go into a volume mounted inside the folder (an NFS home, a bind mount): they stop there and the summary names it, as they already did on this Mac. A move from this Mac to a server stops at a mounted volume too.
- Saving someone else's file with hard links from a root panel no longer splits it: its other names get the new text too.
- In the results of a tag search (a tag in the sidebar), F8, ⇧F8, F5, F6 and ↩ act on the files found. Before, when the panel was in another folder than your home, they acted on files with the same relative names in that folder: ⇧F8 could delete a backup's copy and leave the tagged file. In any search's results and in Git changes, the user menu's %s and %f and **Compress** (⌥F5) take the file found, not one of the same name at the top of the search.
- Extracting a whole archive that can't be read through to the end (a damaged member) into a folder with files in it no longer overwrites them without asking: it unpacks into a hidden folder first, and nothing lands if the archive is broken.
- Extracting an archive on a server no longer overwrites files in the destination without asking when the destination couldn't be listed (no permission, a refused connection): it says so instead.
- A copy or move on this Mac no longer replaces a file that appeared under the same name while it ran (a download into the same folder during a long copy): that file stays, the new one takes the next free name, and the summary says so.
- What you type into the editor while **Save as Administrator** waits for your password now stays unsaved. Before, the window counted as saved once the root write was done, and closing it lost those lines without a question.
- Closing the main window while an editor with unsaved text is in the Dock no longer asks the quit question and then never again: the app stays open with the editor, and ⌘Q later asks about the unsaved text as it should.
- A server file opened in another app (↩) and saved there just before you quit Kermo is no longer lost: the quit question names it, and its copy is kept instead of removed. Before, a save less than two seconds old hadn't reached the server and its copy was deleted.
- A settings file that's there but can't be read (say `servers.json` owned by root after a `sudo` edit) is no longer taken as missing and replaced at the next save: Kermo says so at launch and leaves it as it is. An unreadable `usermenu.json` or `filters.json` is reported instead of being replaced with the examples.
- After the editor reloads a file that changed on disk, ⌘Z no longer applies the old text's edits to the new one (which garbled it, and a save then wrote that over the change).
- **Delete** (F8) on a server skips an item that's something else by now than the panel listed (a file rewritten or replaced, a folder where a file was), and names it: a server's panel isn't refreshed by itself, and a server has no Trash. A folder that is still a folder is deleted as before.
- **Overwrite** in "changed on the server since you opened it" replaces only the version that question was about. If the file changed again while the question or Compare's diff was up, Kermo asks again instead of writing over a change you never saw.
- **Synchronize Folders** no longer copies `README` on one side over `readme` on the other as if they were one file: when the two differ, the row is a conflict and both stay. Between two servers they are often unrelated files.
- A server file's history keeps the version from before a run of saves (an app's autosaves seconds apart no longer push out the file as it was when you began), and reverting to the oldest version kept updates its open editor.

## [1.2.1] - 2026-10-17

### Changed

- **Server sheet:** a saved password shows as dots, and the eye beside it shows it after Touch ID or the Mac password (every time). Shown and left as it was, it isn't saved again.

## [1.2] - 2026-10-16

### Added

- **Copy SSH Key to Server…** (a server's sidebar menu and ⌘⇧P): puts this Mac's public key into the server's `~/.ssh/authorized_keys` over the connection you already have (one login, the key on stdin), adds it only if it isn't there, then logs in with the key alone to check it took. The server's own key file, else `~/.ssh/id_ed25519`, `id_ecdsa` or `id_rsa` (several: pick one; none: the `ssh-keygen` command to make one). A locked server asks for Touch ID, a production one asks first and logs it. Afterwards a saved server without a key file gets this one, and a saved password can be forgotten.
- **Services…** (⌘⇧P, a server's sidebar menu): the server's systemd services, failed first, each with its state and description. ↩ shows `systemctl status`, ⌘L its log as it goes (`journalctl -f`), ⌘E opens its unit file in the editor, ⌘R restarts it as root through the server's `sudo` (`sudo -n`, else the sudo password, as a reload after a save). On the server of the active panel or SSH tab, or one you pick; a locked server asks for Touch ID.
- **Containers…** (⌘⇧P, a server's sidebar menu): the server's docker (or podman) containers, running first, with their status and image. ↩ shows its log as it goes, ⌘R restarts it, ⌘C copies its name. A restart on a production server asks first (↩ is Cancel) and goes into the production log. Only names made of the characters systemd and docker allow are put into commands. A log stopped with ⎋ stops on the server too.
- **Viewer:** `e` shows errors and warnings only, then errors only, then all lines, with `&` or without (`&` now matches lines as shown, colors' codes aside); `l` shows line numbers (files up to 4 MB, remembered). Following, a scrolled-up view says `paused — End resumes`.
- **Free space on the server** in a server panel's status line: `🌐 sftp · web1 · 120 items · 120 GB free` (`df`'s Available), asked with the listing at no extra wait.
- **Text previews of configs:** ⌃Q and ⌘Y show as text a file Quick Look shows only as an icon — `.conf`, `.env`, `.bak`, `syslog.1`, `server.key`, no extension — when its start reads as text. ⌃Q shows it itself with F3's colors and line numbers (the first 256 KB); ⌘Y through a read-only `.txt` copy for you alone, gone when Quick Look shows something else or closes, and at quit. On a server too.
- **Copy Here As…** (⇧F5, ⌥⇧5): a copy next to the item under a new name (`nginx.conf.bak`, `.bak` selected), or a suffix for each of several marked; folders whole; a taken name is an error, never replaced. On a server the server copies it where it can; a production one says so and logs it.
- **New File…** (⇧F4) on a server and a root panel: an empty file there, never over an existing one, opened in the editor.
- **A folder's context menu:** right-click empty space or `..` for New File…, New Folder…, Paste, Open in Terminal (SSH Here on a server), Copy Path, Reveal in Finder, Get Info, Show Hidden Files, Sort By, Calculate Folder Sizes, Git Changes, and a server's Services… and Containers…. An item's menu gains New File… and Copy Here As….
- **Used and free space in Locations:** `110 GB / 350 GB` right of a volume's name, used in red, free in green, in whatever room the name leaves (all of it in the tooltip). Read again every 30 seconds while Kermo is in front and after each file operation. Volumes… (⇧⌘V) counts free space the same way, as Finder does.
- **Mount and Unmount:** Locations lists in gray the volumes of plugged-in external or removable disks that aren't mounted, with ⊕ to mount one (a click on the row mounts and opens it, as ↩ does in Volumes…). A volume's right-click menu has Unmount (the disk stays plugged in) next to Eject, and ⇧⌘P has **Unmount Volume**. A spinner shows while either runs.
- **The session comes back:** after a restart, the active panel, each tab's cursor (by name) and the dividers between the panels, besides the tabs. Server tabs come back too, not connected: the header says where (`#` for a root panel), and ↩ connects — Touch ID first on a locked server, a root tab as root. Nothing connects by itself at launch; ⌘↑ goes to the tab's folder on this Mac.
- **Copy and paste with the mouse in the terminal, as in PuTTY:** selecting text copies it, a right-click pastes (⇧-right-click in mc, htop and the like). Several lines pasted into a production server's or a `root@` SSH tab whose shell runs each line as it comes ask first. `terminalCopyOnSelect` and `terminalRightClickPaste` turn either off.
- **Enable Touch ID for sudo** (Admin menu, ⇧⌘P): `sudo` in a terminal takes your fingerprint. Kermo asks, then writes `/etc/pam.d/sudo_local` from macOS's template with the `pam_tid.so` line on (your own lines kept); macOS asks for your password once. It survives macOS updates.
- **⇧F10 and the Menu key** of a PC keyboard open the cursor item's context menu by its row (the folder's on `..`). **Sort by Name / Size / Modified** and **Reverse Sort Order** are commands in ⇧⌘P.

### Changed

- **Folder sizes on a server** (Space, ⌥Space) come from the server's own `du`, one command for all the folders, instead of an SFTP walk of every folder: much faster on a large or distant server. A folder `du` couldn't read all of shows as `≥ 1.2 GB`; ⎋ stops `du` on the server too; a root panel's runs as root (`sudo -n`). Where `du` can't run — BSD's has no `-b`, an account without a shell, sudo that allows only `sftp-server` — the folders are walked as before.
- **Cancel** in the status line, in red, next to whatever ⎋ stops there (folder sizes, connecting, a download…): the same for the mouse.
- The sidebar's `⇄` is green while a server's tunnels listen, as SSH and SFTP are when open (red still when one failed).
- A server row's buttons (SSH, SFTP, Tunnels, ⋯) and the Git section's take clicks around their icons, not only on them.
- **A changed host key** is said plainly wherever a connection fails — reinstalled server or someone intercepting, the new fingerprint, the old key's file and line — instead of ssh's banner. Opening a server's files, the alert offers **Remove Old Key…** (↩ is Cancel), then connects again and asks about the new key; on a production server it asks you to check the fingerprint with the admin first.
- **Extracting all of a tar** (⌥F9 on a `.tar.gz`, `.tar.xz`…) no longer reads the archive once first just for the names at its top: into an empty or new folder it unpacks straight in; into one with things in it, it unpacks into a hidden `.kermo-extract-…` folder there, then asks **Keep Existing** / **Overwrite** / **Cancel** if any of it is there already (Cancel removes what was unpacked) and moves it out. A tar that fails or is stopped leaves nothing behind. Zip and 7z are as before.
- **A copy on this Mac's own disk** starts at once and counts its total alongside (`counting…`, a moving bar) instead of walking everything first. Sticks, shares and disk images count first, as before.
- ↩ or F3 on a file inside a tar stops reading the archive at that file.
- **Forward Port…, Services…, Containers… and Run on Servers…** keep the server's connection for its idle time (10 minutes, 60 seconds for a locked server) even when no panel shows the server, as plain ssh does: the next look needs no login or password. Before, the next change of any panel ended it. Disconnect ends it; a locked server's ends when the screen locks.
- **Terminal colors** show as colors in the viewer and in output windows (and Run on Servers'), instead of escape codes in the viewer and nothing in output windows; errors stay red, and a colored log line isn't also tinted by its level.
- **A volume that won't eject** says who holds it, for example `Couldn't eject “KINGSTON”: in use by Preview, zsh`, from `lsof`, instead of only macOS's "in use".
- Editing a server file only root may write, from a user's panel, says in the editor that saving it needs the panel as root (⌃⌘R).
- **Info's checksums:** the first of MD5, SHA-1 and SHA-256 you press reads the file once for all three; the others then show at once. A read error is said in the system's words.
- Faster on this Mac: folder sizes, copies and Find Files no longer look at each subfolder on its own to stay on one volume; merging copies, Find Files by content and Compare contents do less work per file; `git status` in a slow repository runs at most every twice its own time (still at most once a second).
- **A folder of more than 5,000 items sorts in the background** (a column header clicked, search results done, links found to be folders, a server folder listed): the list stays as it was until it's done, `Sorting…` shows after a moment, and the cursor stays on its item. A million names held the window for a second.
- Big folders and files no longer hold the window: the quick filter folds the names once instead of on every key (a million names: 0.3 s a key to ~15 ms); ⌥Space over thousands of folders no longer adds up the whole list per folder (4000 folders among 200,000 items: 45 s to under 0.1 s); ⇧⌘P stops ranking a query you've typed past and skips names that can't match; the folder watcher's re-list does nothing when nothing changed; the editor's line numbers follow an edit instead of counting a 30 MB file's lines on every key, and its colors repaint only what changed (a 2 MB script: 15 s after each pause in typing to a few hundredths); Open With in the context menu looks up apps when it opens.
- **Copy Path** (⇧⌘C) and **Copy Name** (⌥⌘C) work in a server panel: the paths on the server (they only beeped there).
- **Connect to Server** (⌃⌘K, ⌘K) takes a port followed by a path, `user@host:2222/etc/nginx`, as a URL would; before, it went to port 22 looking for a folder named `2222/etc/nginx`.
- **The production log** names a copy's new name when one item is copied under another (Copy Here As, F5 to a name), not only its folder.

### Fixed

- **Eject of an APFS stick or card** takes the stick itself away. Before, only its volume was unmounted and the stick stayed plugged in.
- The size of `/` and Find Files from `/` counted and found everything under `/System/Volumes/Data` twice (it has `/`'s own device on current macOS); now once.

## [1.1] - 2026-10-14

### Added

- **Server file history:** every save of a server file (F4's ⌘S, a save in another app) keeps the version it replaces on this Mac, in `~/.config/dfilemanager/history.noindex/<server>/<path there>/<name>@<date>`: 20 versions a file and 200 MB in all, the oldest going first. "Overwrite" after someone else's change keeps their version. A file over 5 MB gets none, and the status line says so (and, for a few seconds, the editor that saved); so they do when a version can't be written, and the save goes on. Saving a small file you opened with F4 costs no extra wait: the check before writing already reads it. The folder is owner-only and out of Spotlight and Time Machine; `defaults write com.dmn.dfilemanager serverHistory -bool false` turns it off.
- **Compare Files (⌘⇧D) with a server:** a server's file against this Mac's or another server's, by the same rules as before: two marked files; the cursor's and the same name in the other panel (now looked for on its server too); or the two cursors. A server's file is fetched as the ⌃Q preview fetches it (the copy already here if it's unchanged, up to 64 MB), and `diff -u` and its window's title name it "host:/path" instead of its temporary copy; a `diffCommand` tool gets the copies.
- **Server File History…** (⌘⇧P or the File menu, on a server panel's file or in a server file's editor): the versions its saves kept, newest first. ↩ or F3 views one; ⌘⇧D diffs it with the file on the server now, ⌘D with the version before it; ⌘R reverts the server's file to it through the same save as ⌘S, so a production server asks first, a change made there since the list opened is asked about, and the version it replaces is kept too; the file's open editor shows the version afterwards, unless it has changes of its own. A locked server asks for Touch ID first.
- Versions in the history keep their file's syntax highlighting in the viewer and editor (the date at the end of their name hid the extension).
- **Sidebar:** a server's menu has **Show File History**, which opens its folder of versions in the panel (view, compare or delete them there as any files). Deleting a saved server offers to delete its file history too, unless another saved server at that address still uses it.
- **Saving a server file someone changed meanwhile:** the "changed on the server since you opened it" question has a **Compare** button: it opens the diff of your text with the server's file, then asks again.
- **A server's files as root:** **Open SFTP as Root** in a server's sidebar menu, **Reopen Panel as Root** (⌃⌘R) and **Reopen Panel as User** (⌃⇧⌘R) in the Admin menu and ⌘⇧P. The panel's SFTP runs through the server's own `sudo` (`sudo -n` with NOPASSWD; otherwise the sudo password is asked for in a sheet, tried once on its own with the same command so a wrong one costs a single attempt, and kept in memory for 5 minutes after its last use; **Save in Keychain** keeps it as an item of its own, apart from the ssh password; the server's Edit sheet can forget it). The header and the window's title read `root@host:/path #` in orange (purple on a production server); the command line keeps `user@host $` and says ⌘E runs as the user, not root. Saves go the same way as the user's (history, the production question, "changed on the server"); on a server with SELinux they write into the file instead of renaming a new one over it, so it keeps its label. Nothing pasted, dropped or restored ever opens as root; a locked server asks for Touch ID. When sudo refuses, it says why in plain words (needs a password, requiretty, no sftp-server).
- **Config checks on save:** saving a server config checks it with the server's own tool before it takes the file's place — `visudo -cf` for sudoers, `sshd -t -f` for `sshd_config`, `haproxy -c`, `nft -c`, `docker compose config` for compose files. A failure leaves the file on the server as it was and shows what the tool said; the editor keeps your text unsaved. Checks that work only as root run through `sudo` on a root panel (`sudo -n`, or the sudo password the panel uses) and are skipped on a user's panel, which the status line says; so it does when the tool isn't installed there. Configs with includes are checked in place right after the save — `nginx -t`, `apachectl configtest`, `systemd-analyze verify`, `postfix check`, `named-checkconf`, `sshd -t` for `sshd_config.d` — and when that fails, the text the save replaced is put back at once — a new file is removed — unless someone changed the file meanwhile or it's over 5 MB; the dialog says which. Copies (F5, F6, drag and drop) aren't checked; on a production server the question says so for a file that lands where a save would be checked first. Your own rules go in `~/.config/dfilemanager/validators.json` (**Edit Validators…** in the Kermo menu and ⌘⇧P), looked at before the built-in ones; `"check": null` turns one off.
- **Reload after a checked save:** once a config passed its check, Kermo asks **Reload after saving …?** with the command it runs (`systemctl reload nginx`, `postfix reload`, `rndc reload`, `systemctl daemon-reload` for units …); **Compare** first shows the save's change. It runs as the check did — as root on a root panel; on a user's panel only reloads of your own rules are offered. A production server's question says so and ↩ answers Cancel. When `Port` or `ListenAddress` changed in `sshd_config` and systemd listens for sshd (`ssh.socket`, Ubuntu 22.10 and later), the reload is `daemon-reload` plus a restart of `ssh.socket`, and the question says new connections go to the new port. nftables is never reloaded for you.
- **Production log:** what Kermo does on a server tagged production goes into `~/.config/dfilemanager/audit.jsonl`, a JSON line each (`grep`, `jq`): saves and reverts, commands (⌘E, F2), copies, moves and deletes (F5, F6, F8, Synchronize), renames, permissions, new folders, extracting, reloads — with the time, the server (and whether as root), the paths, the command and how it ended. Command lines may hold secrets, so the file is owner-only; `defaults write com.dmn.dfilemanager auditLog -bool false` turns it off. **Show Production Log** (Admin menu, ⌘⇧P) opens it in the viewer.
- **SSH tunnels on saved servers:** a saved server's sidebar menu ▸ **Tunnels**, **Go ▸ Tunnels** (all servers') and ⌘⇧P (**Tunnels…**, **New Tunnel…**). A tunnel's Forward is written as `ssh -L` takes it — `5432`, `15432:5432`, `15432:db.internal:5432` — and checked as you type; its name defaults to the port's usual one (Postgres, MySQL, Redis, Grafana …), and web ports get **Open in Browser**. Kermo listens on `localhost:<port>` itself (`127.0.0.1` and `::1`, as `ssh -L` does) and takes each connection over the server's shared ssh connection (`ssh -W`): one login with its panels and terminals, and nothing to restart after sleep or a network change — the next connection logs in again. Each tunnel has its submenu (Turn On / Off, Open in Browser, Copy Address, Edit…, Delete…) and a ● — green listening, with its open connections, red when the last one failed (why: in its tooltip, and once in the status line); the sidebar shows `⇄` on a server while its tunnels listen, red when one failed. A port that's taken here is said at once with the next free one ("Use 15433"); a port is never changed for you. Tunnels that were on listen from launch without connecting. Turning one off asks only while connections are open; Disconnect turns the server's tunnels off, and quitting asks only about open connections. A locked server asks for Touch ID to turn one on, its tunnels don't start at launch and stop listening when the screen locks or the Mac sleeps (open connections live on). A password asked for a connection in the background says which tunnel it's for. They're kept in `servers.json` (`"tunnels"`).
- **Forward Port…** (⌘⇧P, Go ▸ Tunnels, a server's sidebar menu): what the server listens on, from its own `ss` (or `netstat` where there's none), one row a port — its usual name, the program where the server shows it (`ss` shows only your own without root), and whether it listens on localhost only, on all addresses or on one address (the tunnel then goes there). ↩ forwards it by a temporary tunnel on the same port here — the next free one when that's taken, and the status line says so; ⌘O also opens it in the browser, ⌘C copies its address, ⌘S saves it as one of the server's tunnels. Ports a tunnel already forwards say where ("→ localhost:15432"). Temporary tunnels work on any server, one that isn't saved too, and last until Turn Off, Disconnect or quitting (a locked server's also stop when the screen locks); they're marked "temporary" in the menus and in **Tunnels…**, with **Save** once the server is saved, and the sidebar shows `⇄` on their server (its tooltip marks them temporary). A locked server asks for Touch ID before its ports are looked at.
- **Run on Servers…** (⌘⇧P, the Admin menu, the sidebar's Servers menu): one command on several servers at once, as F2 runs one on a server — in each server's login shell, without a terminal (so `sudo` only with `-n`). One sheet takes the command and the servers, saved ones and `~/.ssh/config` hosts with check boxes (production in purple, locked ones with 🔒); a filter narrows the list by name or address, ⌘A there ticks all it shows and ⇧⌘A unticks them, and what runs is what's ticked and shown. The last choice and command come back next time. Up to 8 run at once; logins go one at a time, so password dialogs come one after another, and say what they're for. One output window shows each line as it comes under its server's name (`web1 │ …`, errors in red), then a summary: `✓ 5  ✗ 1 (db2: exit 1)  🔒 1 skipped (vault)`; ⎋ stops them all, and again closes the window; once it's over, ⌘R runs it again on the same servers. A command that removes, moves or stops things (`rm`, `mv`, `chmod`, `chown`, `dd`, `systemctl stop|restart`) asks once when production servers are among them, naming them all, with ↩ on Cancel; locked servers ask for Touch ID one after another before anything runs, and one refused is skipped. Each production server's run goes into the production log with its exit status.
- **Git in the sidebar:** while the active panel is in a repository, a Git section at the bottom of the sidebar shows the branch, its changes, ↓↑ to pull and push, and a cloud for a branch no remote has yet. A click opens **Switch Branch…** (⌃B): branches and tags newest first, ↩ switches, a new name creates one, ⌘N branches from the highlighted one, ⌘⌫ deletes a merged one. **Commit…** (⌃⇧C) takes the message in the search window and offers the staged files, all changes, or an amend while the last commit isn't pushed. **Sync** (`pull --ff-only`, then `push`), **Publish Branch**, **Pull**, **Push** and **Fetch** ask for a passphrase in the same dialog as servers, and ⎋ stops them. **Initialize Git Repository…** shows the folder first. Nothing forces, rebases or stashes; when git refuses, a sheet shows what it said.
- **Documentation:** the README is a short overview with an index, and the manual is in `docs/`, one page per topic: install, getting started, panels and search, files, viewer and editor, Git, terminal, servers, root panel, config checks, tunnels, safety, shortcuts, configuration, troubleshooting. CONTRIBUTING.md says how to build, test and write docs. Screenshots, made with made-up files and servers, show the window, the sidebar's server rows, Forward Port and Run on Servers; a test keeps the shortcut and option tables in step with the code.

### Changed

- **A Git menu:** the Git commands moved there from File and View (their keys are the same), with the new branch, commit and sync commands.
- **Sidebar server rows:** what's open shows as icons — `>_` SSH and a folder for SFTP in green (a count from 2), `⇄` for tunnels (red when one failed) — and the server's icon carries a lock (locked) or a red dot (its last connection failed). Under the mouse: SSH, SFTP, Tunnels and ⋯, the server's whole menu; Edit, Pin and Close All Sessions are there now. Names get the room: at 180 pt they no longer shrink to a few letters.
- **Server pickers** (Connect, Forward Port) mark production servers `🟣 PROD`, as they mark locked ones `🔒`.
- **Output windows** (⌘E ⇧↩, a server panel's commands, Extract, Compress …): ⎋ stops the command and keeps the window with what it printed; ⎋ again, or once it's over, closes it. It used to close at once.
- **The tunnel sheet:** back with "Port N is in use", ↩ takes the free port it offers ("Use N+1") instead of trying the taken one again.
- **Production servers are marked in purple**, not red, in the sidebar, menus and headers, and titles say `🟣 PROD`: red is left for what failed.
- **Speed:** undo and redo of a move, undo of a copy and batch rename do their disk work in the background: thousands of items on a network share no longer freeze the window. So do rename, Go to Link Target, diff, compress, `fm` and Info's chmod, chown and flags: a share that stopped answering doesn't hang the app.
- **Speed:** "Scanning…" before a copy or move from a server reads the tree a level at a time, up to 64 folders together, instead of one folder after another: thousands of folders on a distant server take seconds, not minutes. A folder skipped in a conflict isn't read a second time.
- **Speed:** deleting on a server (F8, and Synchronize's deletions) takes all the items together: the files 64 at a time, the folders a level at a time, up to 64 listed together with their files deleted together, then the empty folders, deepest first. A file that can't be deleted is still asked about on its own (Retry, Skip, Abort), and the folders above it stay without an error each.
- **Speed:** comparing folders with a server (Compare, Synchronize Folders) reads both sides at once, a level at a time with up to 64 folders together, instead of one folder after another, one side after the other.
- **Speed:** synchronizing with a server checks every item against what Compare saw in one go, up to 64 requests together, and reuses what it saw for the scan and the copy, instead of several requests per item before the first byte.
- **Speed:** reading a file from a server (a download, F3, F4, the check before saving with ⌘S) asks for the end of the file together with its last piece, and doesn't wait for the server to confirm it was closed: two waits less per file. Reading a server folder (opening it, a scan, Compare, a delete) doesn't wait for its close either.
- **Speed:** a big server folder opens several times faster: up to 8 requests for its names are in flight together instead of one at a time (10 000 names: 13 waits instead of 100). Scans, Compare and deletes keep up to 4 a folder in flight, so a level of small folders is read in one wave.
- **Speed:** downloading a server folder takes each item's kind, size, date and mode from the folder's listing instead of asking the server again: with the two changes above, a small file costs 2 waits instead of 5.
- **Speed:** a file copied to a server gets its close, mode and date sent right behind its data instead of after the server confirmed the data: one wait less per file. A file whose owner can't write it still waits, so one that fails half-way stays writable for Retry.
- **Speed:** copying a folder to a server doesn't ask whether each name is taken in the folder it has just made there (nothing can be yet; a name that differs only in case from one copied before is still asked about): one wait less per file. With the change above, a small file uploads in 4 waits instead of 6.
- **Speed:** saving a server file you edit (F4, ⌘S) sends its mode along with the close, right behind the data, and checks that the server's copy hasn't changed with a single read: 8 waits instead of 12.
- **Speed:** saving a server file (⌘S, another app's save, Revert) goes over the session of the panel showing that server, when one does: no ssh start and handshake of its own, and from a root panel no second sudo run. The panel's folder listings wait for the save meanwhile.
- **Speed:** a server panel keeps one connection to its server while it shows it, instead of opening a new one for every folder: going into a folder skips the ssh start and handshake (about 0.1 s on a local network, several round trips to a distant server). After sleep or a network change the next folder connects afresh. A locked server's connection therefore stays open while a panel shows it; the lock itself still lasts 5 minutes.

### Fixed

- **Timeouts fire on time while the app is busy:** a git that hangs is stopped, and a server gone silent cut off, after their set time even when many listings wait on slow disks at once; their timers shared threads with that work and could come seconds late.
- **⎋ on a command over ssh** (a config check, a look at a server's ports) no longer waits until the command on the server ends: ssh's shared connection kept the command's error output open until then.
- A server's shared connection was stopped right after its first folder listing in a panel, so the next save, preview, copy or root panel logged in again (asking for the password again where ssh needs one).
- **Panels:** a folder reloading by itself (or after a save to its server) no longer wipes the status line's "… ⎋ cancels" of an operation still running there, or a message shown a moment before.
- **Panels:** symlinks to folders no longer turn into files (shown with their own size and sorted with the files) after a folder reloads by itself.
- **Stop and ⎋:** ⎋ stops counting folder sizes on this Mac, as on a server, and so does leaving the folder; closing Info stops its folder count; Stop during "Scanning…" before a copy stops at once instead of after the whole tree. Search by content and compare by content stop within a big file instead of after it; closing Info stops its checksums.
- **Info:** a checksum of a file that fails to read part-way shows the read error instead of a hash of the part that was read.

## [1.0] - 2026-10-10

The first public release. Kermo was previously called DFileManager; settings and permissions carry over.

### Added

- **Panels:** 2–4 panels with tabs, a Places sidebar (Favorites, Frequent, Locations, Servers, Tags), a directory tree, a quick filter with presets, and Quick View. Large folders load in the background without freezing the window.
- **Keyboard:** MC-style marking, a key bar that shows shortcuts for held modifiers, toolbar search for commands, folders and files (⌘⇧P), a cheat sheet (F1), and a keymap editor. Shortcuts work with any keyboard layout.
- **File operations:** a background queue with pause, speed and ETA, a conflict dialog, APFS clones, undo/redo, Put Back from the Trash, batch rename, folder sizes, links, split/combine, and Finder tags.
- **Viewer and editor:** a viewer for multi-gigabyte files (mmap) with hex, plist/JSON, follow (`tail -f`) and line filter modes; an editor with syntax highlighting, line numbers and Save as Administrator.
- **Search and compare:** search by name, content or Spotlight with results as a panel; compare and synchronize folders (two-way or mirror), including with a server; diff two files.
- **Archives:** browse zip/tar/7z as folders, extract, and create archives.
- **Servers:** SFTP panels and SSH sessions through the system OpenSSH (`~/.ssh/config`, agent, ProxyJump). Copy and move between this Mac and servers, and from server to server, with resume after a dropped connection. Saved servers with Keychain passwords, Touch ID locks and a production tag that asks before changes. SMB, NFS and AFP mounts.
- **Terminal:** a built-in terminal (⌃O) whose panel follows `cd`, with SSH tabs; ⌘E commands and the F2 user menu run in it.
- **Git:** a status column, branch and ahead/behind in the status bar, changes-only views, diff against HEAD, log, blame, stage and unstage; the status column and branch work on servers too.
- **Admin:** Info window with permissions, owner, xattr, ACL, hashes and signature; chmod, chown, copy, move and delete as administrator.
- **Themes:** System, Midnight Commander, Far Manager and 10 more.
- **`fm` command** to open folders from the shell.
